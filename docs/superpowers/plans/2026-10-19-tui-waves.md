# TUI update-all waves + in-TUI Claude extract — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two TUI keys run every linker through select → validate in two waves, and the extract step runs `claude -p` in the background instead of telling the operator to switch panes.

**Architecture:** A pure `Wave` state machine (`octirb/tui/wave.py`) emits one action at a time (an octi-rb argv or a Claude extract) and is fed each exit code; `screen.py` drives it from its existing tick loop through the existing single `Job`. `octirb/tui/extract.py` builds the locked-down `claude` argv and condenses its stream-json into pane lines. One CLI addition, `select --reports-from-run`, scopes actor-target's report source to a prior run's reports.

**Tech Stack:** Python 3.11+ stdlib only (`curses`, `subprocess`, `json`, `shutil`), pytest, ruff, mypy --strict.

**Spec:** `docs/superpowers/specs/2026-10-17-tui-design.md` — read the whole file; the "Addendum (2026-10-19)" section is what this plan implements.

## Global Constraints

- Standard library only; no new runtime dependencies.
- Lint clean: `ruff check octirb/ tests/ contrib/` and `mypy --strict octirb/` with zero findings.
- Functions ≤ 60 lines, ≥ 2 checks per function (input validation + invariant/postcondition, `raise`, not `assert`); every loop bounded.
- No `bypassPermissions`, no `--dangerously-skip-permissions`, no Bash tool for the Claude subprocess.
- Nothing a wave runs may write to the platform: wave steps are only `select`, `fetch`, `batch`, `structured`, extract, `validate`.
- Wave run ids: `f"{stamp}-w{n}-{tag}"`, `stamp` = `%Y%m%dT%H%M%SZ` UTC, `tag` = linker name (actor-target's tag is `actor-target`).
- Claude argv (exact): `[claude, "-p", prompt, "--tools", "Read,Write", "--allowedTools", "Read", f"Edit(/{run_dir.resolve()}/extractions.json)", "--permission-mode", "dontAsk", "--strict-mcp-config", "--output-format", "stream-json", "--verbose", "--restricted"]`, run with cwd = run dir. (`--restricted` confines Read/Write to the working directory; without it Read is allowed on any path even under dontAsk — verified 2026-10-19.) (The leading `/` plus the absolute path gives the `//abs` form Claude Code needs; verified on 2.1.303.)
- Do not commit. The user commits; leave changes in the working tree (the TUI itself is still uncommitted on `feat/tui`).

## Review Focus

1. Claude exits 0 but writes nothing (permission denied, gave up) → wave must treat it as failed, not run validate on a missing file. Test in Task 4.
2. Wave 2 pressed before any Wave 1 exists → refuse with a clear message, start nothing. Test in Task 4.
3. A Wave 1 run whose select failed has no `selection.json` → `--reports-from-run` must skip unreadable/missing runs rather than crash Wave 2's select; CLI should exit `EXIT_BAD_RUN` only when *no* named run has a readable selection. Test in Task 1.
4. `claude` emits non-JSON or unknown event types on stdout → `condense` returns the raw line (truncated) or `None`, never raises. Test in Task 3.
5. Operator presses `1` while a single step is running, or `Enter` on a step while a wave runs → refused with a message; one job at a time. Test in Task 5.

### Task 3: `octirb/tui/extract.py` — Claude argv, prompt, stream condensing

**Files:**
- Create: `octirb/tui/extract.py`
- Test: `tests/test_tui_extract.py`

**Interfaces:**
- Produces:
  - `find_claude() -> str | None` — `shutil.which("claude")`.
  - `extract_prompt(linker: str, run_dir: Path) -> str` — raises `ValueError` for a linker with no model step (`report-vuln`, `report-labels`) or unknown.   - `claude_argv(claude: str, run_dir: Path, prompt: str) -> list[str]` — exactly the argv in Global Constraints.
  - `condense(line: str) -> str | None` — one stream-json line to one pane line, ≤ 200 chars:
    - not JSON / not an object → the raw line truncated;
    - `type == "assistant"`: for each content block, `tool_use` → `claude: <name> <basename of input.file_path or "">`, `text` → `claude: <first non-empty line>`; several blocks join with `"; "`; nothing → None;
    - `type == "result"` → `claude: done (<subtype>)` plus `: <first line of result>` when present;
    - `type == "user"` with a `tool_result` whose `is_error` is true → `claude: denied/error: <first line of content>`;
    - everything else → None.
- Consumes: nothing new.

### Task 4: `octirb/tui/wave.py` — the pure wave state machine

**Files:**
- Create: `octirb/tui/wave.py`
- Test: `tests/test_tui_wave.py`

**Interfaces:**
- Consumes: `state.steps_for`, `state.build_argv`, `state.Options`, `state.summarize_run` (Task-independent, already exist); `extract.extract_prompt`, `extract.claude_argv` (Task 3).
- Produces:
  ```python
  WAVE_LINKERS: dict[int, tuple[str, ...]] = {
      1: ("report-location", "report-sector", "report-actor", "report-vuln"),
      2: ("report-labels", "actor-target"),
  }
  CHAIN = ("fetch", "batch", "structured", "extract", "validate")

  @dataclass(frozen=True)
  class Action:
      kind: str            # "octirb" | "claude"
      argv: list[str]      # octi-rb subcommand argv, or the full claude argv
      run_id: str
      step: str            # "select" | "fetch" | ... | "extract" | "validate"
      cwd: Path | None     # run dir for claude, None for octirb

  def latest_wave1_ids(runs_dir: Path) -> list[str]
      # run dir names matching r"^\d{8}T\d{6}Z-w1-" grouped by stamp; newest stamp's ids, sorted; [] if none

  class Wave:
      def __init__(self, number: int, runs_dir: Path, claude: str | None, stamp: str) -> None
          # ValueError for number not in WAVE_LINKERS;
          # wave 2 with latest_wave1_ids(runs_dir) == [] -> ValueError("wave 2 needs a wave 1 run first: press 1")
      def next_action(self) -> Action | None   # None when done or cancelled
      def finished(self, exit_code: int) -> None   # feed the exit of the action last returned
      def cancel(self) -> None
      @property
      def done(self) -> bool
      @property
      def run_ids(self) -> list[str]   # runs created so far, in order
      def summary(self) -> list[str]   # one line per linker
  ```
- Behaviour:
  - Per linker: select argv = `["select", "--linker", L, "--run-id", run_id]`, plus for actor-target `["--source", "report"]` and one `["--reports-from-run", id]` per wave-1 id. Then each `CHAIN` key present in `[s.key for s in steps_for(L)]`, in `CHAIN` order; command steps via `state.build_argv(key, run_id, state.Options())`; `extract` → `Action("claude", claude_argv(claude, run_dir, extract_prompt(L, run_dir)), run_id, "extract", run_dir)`.
  - After select exits 0: if `summarize_run(run_dir)` is None or its `selection` count is 0 → outcome `empty`, next linker.
  - Nonzero exit at any step → outcome `failed at <step> (exit N)`, next linker.
  - Extract exit 0 but `run_dir/"extractions.json"` not a file → outcome `failed at extract (no extractions.json)`.
  - Reaching extract with `claude is None` → outcome `needs extract: claude not on PATH`, next linker (no action emitted for it).
  - After validate exits 0 → outcome `ok`; summary line `f"{L:<16} {run_id}  sel {sel}  auto {auto}  review {review}"` from `summarize_run` counts; other outcomes → `f"{L:<16} {run_id}  {outcome}"`.
  - `finished` with no outstanding action → `RuntimeError`. Total actions bounded: raise `RuntimeError` if more than `len(linkers) * (len(CHAIN) + 1)` actions are emitted.
  - `cancel()` → `done` true, remaining linkers get outcome `cancelled`, current one too if unfinished.
