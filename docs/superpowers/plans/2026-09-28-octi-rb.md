# octi-rb Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build octi-rb, a single stdlib-only Python CLI plus Claude Code plugin that enriches any OpenCTI platform's relationships: report containment for Location/Sector/Actor/Vulnerability and explicit actor → location/sector relationships, all config-driven and revertable.

**Architecture:** One package (`octirb/`) with a fixed linker registry over a shared pipeline (select → fetch → batch → Claude-extraction → validate → apply → revert), one typed ledger per run, and a TOML config. Proven modules are ported from `~/opencti-docker` (paths given per task) with their tests; new seams (config, crosswalk, vuln linker, alias write-back, tiered text cache) are built TDD.

**Tech Stack:** Python 3.11+ standard library only (`urllib`, `tomllib`, `argparse`, `shutil`). Dev tooling: ruff, mypy --strict, pytest, shellcheck.

**Spec:** `docs/superpowers/specs/2026-09-28-octi-rb-design.md`

## Global Constraints

- Python ≥ 3.11, **zero runtime dependencies** (stdlib only; no pycti/requests).
- Quality gate every commit: `ruff check octirb/ tests/ bin/octi-rb` clean, `mypy --strict octirb/` clean, `pytest -q` green, `shellcheck install-deps.sh` clean. All pinned in `pyproject.toml` (copy `[tool.ruff]`, `[tool.mypy]`, `[tool.pytest.ini_options]` sections from `~/opencti-docker/pyproject.toml` verbatim, adjusting paths).
- Power of 10: every loop bounded; ≥2 raising checks per function (input + invariant); functions ≤ 60 lines; no `eval`/`exec`/string-built commands; errors never suppressed undeliberately.
- Unix: data → stdout (line-oriented/JSON), diagnostics → stderr, no banners/ANSI. Exit codes: `0` ok, `1` operational failure, `2` bad run/config state.
- Labels: configurable prefix, default `AI-` → `AI-Location`, `AI-Sector`, `AI-Actor`, `AI-Vulnerability`, `AI-Relationship`, `AI-Created`.
- Credentials only from `$OPENCTI_TOKEN` / `$OPENCTI_ADMIN_TOKEN` or a config-named env file. Never in config.toml, never committed.
- Only `confidence: high` auto-applies; review items carry `hard_fail`; `--include-review` never promotes `hard_fail: true`.
- Nothing invents entities except `apply --create-missing` (actors only). Dry-run mutates nothing, ever.

## Review Focus

Failure modes the spec implies but which need explicit tests (each pinned to its owning task):

1. **Config typo or invalid regex** — a misspelled key (`fecth_enabled`), wrong type, or bad `exclude_title_patterns` regex must abort at startup naming the offending key/pattern, never fall back silently to defaults. → Task 2 tests `test_unknown_key_rejected`, `test_invalid_regex_named`.
2. **Malformed `extractions.json`** — a non-array file, or non-dict items inside it, must become hard-fail review items (or a named exit-2 error for the non-array case), never a traceback. → Task 12 test `test_validate_non_dict_item_held`, `test_cmd_validate_non_array_exit2` (Task 13).
3. **Empty sector vocabulary** — a platform without any sector authored by `canonical_authors` (e.g. Filigran datasets connector never ran) must fail `select`/`doctor` with a message naming the configured authors, not proceed with a vocabulary of zero. → Task 7 test `test_empty_canonical_vocabulary_exits`.
4. **Missing/corrupt crosswalk cache** — actor resolution with `crosswalk_enabled = true` but no readable cache must log one stderr warning and continue platform-only, never crash or half-resolve. → Task 8 test `test_corrupt_cache_returns_none`, `test_resolver_without_crosswalk_still_resolves`.
5. **Fetch cap reached mid-run** — hitting `max_fetch_per_run` must mark remaining fetch-tier reports `skipped (fetch cap)` in `fetch_status.json` and say so in `status`, so a half-fetched run is visible rather than silently thin. → Task 11 test `test_fetch_cap_marks_remaining_skipped`.

VULNS_BY_NAME_Q = """query($names: [Any!]!) {
  vulnerabilities(first: 500, filters: { mode: and, filters: [
    { key: "name", values: $names }], filterGroups: [] }) {
    edges { node { id name } } } }"""

ALIAS_PATCH_M = """mutation($id: ID!, $input: [EditInput]!) {
  stixDomainObjectEdit(id: $id) { fieldPatch(input: $input) { id } } }"""


def vulnerabilities_by_name(self, names: list[str]) -> dict[str, JsonDict]:
    if not names:
        raise ValueError("vulnerabilities_by_name needs at least one name")
    wanted = [n.strip().upper() for n in names if n and n.strip()]
    if len(wanted) > 500:
        raise OpenCTIError(f"refusing to look up {len(wanted)} names in one query (max 500)")
    edges = self.gql(self.VULNS_BY_NAME_Q, {"names": wanted})["vulnerabilities"]["edges"]
    out: dict[str, JsonDict] = {}
    for e in edges:
        node = e["node"]
        out[str(node["name"]).upper()] = {"id": str(node["id"]), "name": str(node["name"])}
    return out


def _alias_patch(self, entity_id: str, alias: str, operation: str) -> None:
    if not entity_id or not alias.strip():
        raise ValueError("alias patch needs an entity id and a non-empty alias")
    patch = [{"key": "aliases", "value": [alias.strip()], "operation": operation}]
    result = self.gql(self.ALIAS_PATCH_M, {"id": entity_id, "input": patch})["stixDomainObjectEdit"]
    if not result or not result.get("fieldPatch"):
        raise OpenCTIError(f"alias {operation} on {entity_id} returned nothing")


def add_entity_alias(self, entity_id: str, alias: str) -> None:
    self._alias_patch(entity_id, alias, "add")


def remove_entity_alias(self, entity_id: str, alias: str) -> None:
    self._alias_patch(entity_id, alias, "remove")
